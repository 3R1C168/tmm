### 3.1 Telegraph 链接即时预览 + 站内阅读 + 图片下载（核心新功能）

**背景**：Telegram 频道消息内嵌 Telegraph 链接时，消息自带 `MessageMediaWebPage` 预览（标题/描述/站点/配图 URL），数据免费附带、无需额外 RPC。正文阅读走 Telegraph 官方 JSON API（`getPage?return_content=true`），无需解析 HTML。

| 文件 | 改动 |
|---|---|
| `app/chat/messages.go` | `MessageInfo` 加 `LinkPreview` 字段；`linkPreviewFromMessage()` 提取 `MessageMediaWebPage`（title/desc/site/url/hasPhoto） |
| `server/media.go` | `resolveThumb` 加 WebPage 分支——预览配图经 `/api/media/{id}/{msg}/thumb` 管线加载 |
| `server/telegraph.go`（新，409 行） | 三个接口：`/api/telegraph/{id}/{msg}/read`（阅读）、`/download`（图片批量下载）、`/api/telegraph/img`（图片代理） |
| `server/server.go` | 注册路由 |
| `web/app/src/components/TelegraphReader.vue`（新） | 全屏阅读弹层：标题栏 + 递归渲染正文节点树 + 「下载图片」按钮 |
| `web/app/src/components/TelegraphNode.vue`（新） | 递归渲染 getPage 节点树，白名单标签防 XSS，图片走后端代理 |
| `web/app/src/views/Messages.vue` | 消息卡片渲染链接预览卡片（配图+标题+描述+站点），点击 Telegraph 开站内阅读 |
| `web/app/src/api/index.js` | 新增 `telegraphRead` / `telegraphDownload` / `telegraphImgUrl` |

**接口细节**：
- `GET /api/telegraph/{id}/{msg}/read` → 取消息 → 提取 Telegraph URL → `getPage` → 返回 `{url,title,desc,author,views,content}`（content 是节点树数组）
- `POST /api/telegraph/{id}/{msg}/download` → getPage 收集所有 `<img>` src → 4 并发直连下载到 `<下载目录>/<频道ID>_<消息ID>/`，已存在跳过，失败不中断 → 返回 `{dir,total,success,failed,errors}`
- `GET /api/telegraph/img?url=` → 图片代理（详见 3.3 修复）
- 网络：`telegraphClient` 直连出网（`&http.Client{Timeout: 30s}`），**不走 Telegram MTProto 代理**

### 3.3 Bug 修复：Telegraph 图片不显示（关键！）

**现象**：站内阅读弹层图片不显示（naturalWidth=0）。

**根因**：图片代理 `handleTelegraphImg` 用 `telegraphPathFromURL` 校验**只允许 telegra.ph 域名**，但真实 Telegraph 文章图片常在**第三方图床**（实测 Exhentai 图鉴的文章图全在 `pic.850123.xyz`）→ 400 拒绝。

**修复**：改为 `validateProxiedImageURL()`——允许任意公网 http(s)，拒绝非 http(s) + 内网/本机/保留地址（SSRF 防护：`127.0.0.1`/`localhost`/`169.254.169.254`/`::1` 等，`net.LookupIP` 校验 `IsGlobalUnicast`）。单测 `TestValidateProxiedImageURL`。

**验证**：修复前 15 张图全失败；修复后滚动到底部 15 张全加载（lazy 加载，需滚动触发）。

## 8. 本会话重要教训

1. **Telegraph 文章图片常在第三方图床**（非 telegra.ph）——代理不能只放行 telegra.ph 域名，但必须保留 SSRF 防护（内网/本机/云元数据拒绝）
2. **`tg.Message` 的 `GetMedia()` 依赖 `SetMedia` 设置的 flag**（bit 9）——测试里直接赋值 `Media` 字段拿不到，要用 `SetMedia`
3. **`tmedia.GetMedia` 不处理 `MessageMediaWebPage`**——`resolveMedia` 对网页预览消息返回"没有可下载的媒体"（所以预览配图不走 resolveMedia，靠 `resolveThumb` 的 WebPage 分支）
4. **`data.kv` vs `data/data/<ns>`**：bolt 存储把 path 当目录、每个 namespace 一个文件；根目录 `data.kv` 是 legacy 迁移源，不是当前存储
5. **`fsutil.PathExists` 用 `os.Stat`，目录也算存在**——`data/data`（目录）存在会导致迁移不触发
