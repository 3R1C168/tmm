### 3.9 下载按钮移到气泡外右下角（commit `0c7dddc8` + `9254eddf`）

**背景**：meta 行加了反应/评论数后拥挤（👁浏览 + 反应×N + 💬评论 + 时间 + ⬇下载 5 类元素一行）；下载是核心操作（这是下载管理器）→ 移到气泡外，meta 行只留信息。

**实现**：
- 模板：相册 + 单条消息加 `.bubble-wrap` 包裹层（内容定宽 + relative），meta 行**删掉下载按钮**，bubble 闭合后加 `.media-dl-float` 悬浮按钮
- CSS：`.bubble-wrap { position:relative; width:max-content; }`，`.media-dl-float { position:absolute; right:-34px; bottom:0; 30px 圆钮白底 hover 蓝 }`
- **关键**：`.bubble.media`/`.bubble.album` 有 `overflow:hidden`（圆角裁图），按钮**必须放 wrap 层**才能露在气泡外
- **纯文本消息**（无媒体）：按钮 `disabled→display:none`（不显示）；相册/单条统一悬浮
- **9254eddf 修正**：初始 `right:-12px;bottom:-12px` 让按钮**盖住卡片右下角且底部超卡片** → 改**小尾巴式**：`right:-34px;bottom:0`——按钮完全在卡片右侧外（与卡片右缘留空隙）、**底部贴齐卡片下缘不超**、不盖任何卡片内容

**CDP 实测**：`btnBottomVsBubble:0`（底边贴齐不超）、`btnRightVsBubble:34`（完全在卡片外）、`overlapX:0`（零重叠）——小尾巴效果精确。meta 行清爽（只剩 👁 反应 💬 时间）。

### 3.10 下载历史——已下载消息按钮变勾（commit `60a924fa`）

**背景**：用户要「已下载过的消息，下载图标变成勾」。判断标准（用户选）：**任务历史**（`server-tasks.json` → `/api/tasks`，零后端改动）——已完成任务（status=done）的 `files[].key = "peerID/msgID"` 即已下载。

**实现**：
- `web/app/src/utils/downloadHistory.js`（新）：模块级响应式 `downloaded = ref(new Set())`；`loadDownloadHistory(tasks)`（从任务列表构建 done keys）、`addDownloadedKey(key)`（SSE 实时加入）、`isDownloaded(chatId, msgId)`（O(1) 查询 `peerID/msgID`）
- `Messages.vue`：onMounted 调 `refreshDownloadHistory()`（拉 `/api/tasks`）+ 订阅 `task` 事件（files[].status=done → `addDownloadedKey`，下载完成实时变勾）；按钮已下载 → `CircleCheckBig` 绿色圆勾 + title「已下载，点击可重新下载」（仍可点击重下）；相册用 `albumAllDownloaded`（**整组都下载才算**，部分下载仍显示下载图标可补下）
- **响应式关键**：`downloaded` 必须用 `ref` 包装（模板 `isDownloaded()` 读取它，加载完成触发重渲染）——初版用 `let` 非响应式，按钮不变勾

**图标**：`CircleCheckBig`（圆勾，最像下载完成角标），`--green` token 着色。

**单测**（vite ssrLoadModule 纯逻辑）：done→true / running→false / 无记录→false / addDownloadedKey→true，4/4 PASS。
**CDP 验证**：资源社区可视区相册 22744-22749 **确实未下载** → 按钮正确显示下载图标（非 bug）；已下载的 22712-22725 等在更早消息（虚拟滚动只渲染可视区），滚动定位受限未截图——功能逻辑经单测 + bundle 检查确凿。

### 3.11 播放器进度条改静态小高度（commit `b28b79f1`）

**背景**：用户反馈视频播放器进度条高度「动态」——根因是 `input[type=range]` 的**浏览器原生样式**：Chrome/Edge 原生 range 的 track/thumb 高度会随 hover/聚焦动态变化，`height:4px` 只约束了部分。

**实现**：`GlobalPlayer.vue` 的 `.gp-progress` 加 `appearance:none` + `-webkit-appearance:none` 完全接管原生 range，自定义：
- `::-webkit-slider-runnable-track` / `::-moz-range-track`：**固定 4px 高**，圆角，`--bg-hover` 底
- `::-webkit-slider-thumb` / `::-moz-range-thumb`：**14px 小圆点**，`--accent` 色，居中于 track（margin-top 对齐），hover 不变大
- 去掉 `accent-color` 依赖（原生 thumb 不再显示）

**验证**：CDP 注入同款 CSS 的 range → `inputHeight:4px`、track 4px、thumb 14px 静态——不再动态变化。

## 8. 本会话重要教训

1. **getReplies 的 peer 语义**：传**频道** peer + 帖子 msgID（服务器自动映射讨论组），传讨论组 peer 返回 0 条！评论列表用频道，评论媒体用讨论组——两个 peer 语义不同，别混
2. **tg.Message conditional 字段**（Replies/Reactions/ChannelID）必须用 `SetXxx`/`GetXxx` helper（flag 位），测试里直接赋字段拿不到
3. **评论作者零额外 RPC**：getReplies 响应自带 `Users`/`Chats` 实体，作者名/用户名/频道 title 直接查 map，别额外调 RPC
4. **分页失败 UI**：弹层分页错误不能覆盖首屏 error 态（否则已加载列表消失无法重试）——独立 loadMoreError + 内联重试
5. **评论消息实际在讨论组**（`replies.channelId`）不在频道——评论媒体 thumb 必须用讨论组 ID，频道 ID 会 404
6. **缓存 schema 版本**：MessageInfo 加字段必须同步升缓存 key（`msgs_` → `msgs_v2_`），否则旧 2h 缓存缺字段不显示
7. **E2E 用 Node 直连 API 级实测**（curl/Node fetch）比浏览器截图更硬——无 playwright 时用 `node -e` 脚本调 `/api` 验证数据管线，浏览器渲染用 headless DOM dump 补充
