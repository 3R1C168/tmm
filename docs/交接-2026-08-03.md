## 6.1 本次会话新增（文件级控制 R3-2，2026-08-03）

**功能**：单文件暂停/恢复，不打断任务里其他文件；任务级控制保持原行为。

- **核心机制**：
  - `FileEntry.UserPaused`（model.go）区分「文件级手动暂停」vs「任务级暂停」；任务级 resume 时 `UserPaused==true` 的文件保持跳过。
  - `core/downloader` 加可选 `PauseCheck` 回调（`Options` + `writeAt.WriteAt` 写入前检查）；PauseCheck 返回哨兵 `errFilePaused`（server/dl.go）→ 单文件中止但**不取消整任务**（Critical 修复：原计划用 context.Canceled 会 errgroup cancel 整任务）。
  - `app/dl` iter 加 `paused` 跳过集合 + `requeue` 恢复队列 + `produced` 防双下载；requeue 走独立索引（`peerByID`）不碰主状态机。
  - `dl.Iter` 接口加 `PauseKeys/Unpause/ClearPaused`。
- **API**：`POST /api/tasks/{id}/files/batch`（body `{action: "pause"|"resume", keys: ["peerID/msgID", ...]}`）→ `{results: [{key, ok, error?}]}`。非 running 任务 resume 会触发 `taskManager.resume` 重跑（spec §3.4 step 3）；任务不存在返回 404。
- **前端**（Tasks.vue）：右键菜单「暂停此文件/恢复此文件」（单文件）+「暂停选中 N 个/恢复选中 N 个」（批量）；`api.fileBatchAction(taskId, action, keys)`。
- **关键文件**：`core/downloader/downloader.go`、`core/downloader/progress.go`、`app/dl/iter.go`、`app/dl/finalize.go`、`server/task.go`（fileBatch + iter 接线）、`server/dl.go`（PauseCheck + hook）、`server/handlers.go`、`server/store.go`（并发修复）、`web/app/src/views/Tasks.vue`。
- **验证**（端到端，真实 Telegram）：
  - 运行中暂停 → 文件 `paused+userPaused=true`，任务不被打断；恢复 → 从断点续传；多次 pause/resume 循环无错误。
  - 任务级 pause → resume → 手动暂停文件保持跳过（不被自动恢复）✅。
  - 任务 done 后恢复文件 → 触发任务 resume 只下该文件，完整下载（504MB 视频 504047995/504047995）✅。
  - 单测：core/downloader（PauseCheck）、app/dl（iter pause/requeue）、server（fileBatch/API/404）全绿；`go test ./app/dl/... ./core/downloader/... ./server/...` 通过。
- **store 并发修复**（验证中发现）：并发 upsert（worker run vs handler fileBatch）在 Windows 撞 rename → `store.save()` 改全流程持锁串行化 + 唯一 tmp 文件名。commit `f578327c` `76f72c09`。
- **spec/plan**：`docs/superpowers/specs/2026-08-03-file-level-control-design.md`、`docs/superpowers/plans/2026-08-03-file-level-control.md`。
- **commit**：`a9575871`(core PauseCheck) → `a985e3ae`(dl 透传) → `9c7095a3`+`a526cceb`(iter+server 接线) → `4ee0d992`+`08f88860`(server fileBatch) → `dcb50adc`(web) → `f578327c`+`76f72c09`(store 并发)。

## 6.2 本次会话新增（频道内全文搜索，2026-08-03）

**功能**：频道内消息全文搜索（含 # 标签），服务器 `messages.search` 索引（实测可用），搜索框+下拉结果+点击任意位置跳转。

- **核心机制**：
  - `app/chat/search.go`：`SearchMessages`（封装 `messages.search`，服务器索引秒回，`#` 是普通字符透传）+ `FetchMessageAround`（按 msgid 取上下文定位）+ `ValidSearchQuery`（去 # 后仍有非空白字符才有效，纯 `#`/空白服务器 400）。
  - `server/chats.go`：`GET /api/chats/{id}/search`（q/offset/limit，单飞 + 5 分钟短缓存）+ `GET /api/chats/{id}/around`（msg/limit，取含目标上下文）。搜索 RPC 15s×3 重试（对齐 fetchMessagesFlight）。
  - 前端 `Messages.vue`：消息区头部搜索框 + 防抖 300ms + 空查询不发起 + 下拉结果（缩略图/摘要/日期/总匹配数）+ 滚动续拉 + 点击 around 跳转定位（替换列表进入目标上下文视图）。
- **实测踩坑**：`messages.getHistory` 的 `offset_id` 是**排他**游标（offset=X 返回比 X 旧的，要含目标 X 传 X+1）；不能用 `query.NewQuery + messages.NewIterator`（batchSize=100 会覆盖 limit 且内部维护 offsetPeer 副作用）——`FetchMessageAround` 用原始 RPC。
- **验证**（真实账号，API 端到端）：
  - `search?q=分享` → count=1235，返回带标签消息 ✅；`q=#`/`q=##` → 400（空查询）✅；`q=无结果词` → count=0 ✅；二次查询 cached=true ✅。
  - `around?msg=22689/22731/3210` → 均含目标 msgID ✅。
  - 浏览器 UI 交互（搜索框/下拉/点击跳转）因 IAB 自动化不可靠，**需用户手动验证**。
- **spec/plan**：`docs/superpowers/specs/2026-08-03-chat-search-design.md`、`docs/superpowers/plans/2026-08-03-chat-search.md`。
- **commit**：`3ad2d0e5`(app/chat) → `ed87b049`+`9027a1ba`(server 端点+重试) → `7919ed9c`+`48bb2299`(前端) → `c8c6d769`(around offset 修复)。

## 7. 已知技术债（早期交接延续）

- **IAB 自动化不可靠**：CUA click 坐标偏移，自动化测不准复杂交互，用户手动测试为准
- **FileEntry 在 SkipSame 下不可靠**：SkipSame 跳过的文件 Path 空，删除已用 glob 兜底
- **speed 是 task 级聚合**：文件行速率列显示 `—`
- **localStorage 键**：`tmm.multiSelectMode` / `tmm.taskColumns` / `tmm.collapsedGroups` 等
- **SkipSame 边角**（文件级控制引入）：done 任务中 `FilePaused && !UserPaused` 的残留（SkipSame 命中的被中断文件）不再被标 done，对其 resume 会空转——罕见，未处理
- **Unpause 亚秒竞态**（已知，理论）：正在下载的文件若在 PauseCheck 中断窗口内被用户 pause+unpause（几百毫秒内），requeue 产出与主循环到达可能双下载同一 .tmp——概率极低，E2E 多轮未复现，未修
