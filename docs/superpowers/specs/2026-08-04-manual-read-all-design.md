# 手动全读按钮 + 移除视口自动已读 设计（2026-08-04）

## 背景

视口自动已读（会话 4 已实施）实测功能正常，但体验不佳：
- **未读分隔线变来变去**：滚动时 `readHistory` 推进分界，分隔线位置随视口最大 id 变动
- **左侧会话列表频繁刷新**：每次 `doMarkRead` 都调 `refreshChatsUnread()`（`loadChats(true)`），列表重取

用户决策：**移除滚动视口自动已读，改为手动按钮一键全读**（弹确认框防误触）。交互更简洁、可预期。

## 目标

1. 移除视口自动已读的全部触发逻辑（未读线不再自动变动、左侧列表不再频繁刷新）
2. 标题栏新增「全部已读」按钮：弹确认框 → 确认后当前频道全部已读
3. 标题栏按钮布局调整（从右到左：刷新、全部已读、按范围下载、下载所选、只看媒体、搜索框）
4. 「只看媒体」从 checkbox 改为按钮（点击高亮激活态）
5. 移除「跳到未读末尾（全部已读）」按钮；右下角浮动按钮改为点击直接跳到最后一条消息（最新）
6. 「加载更早的消息」改为底部中央悬浮按钮（不占布局流，滚动时浮动）
7. 未读分隔线保留，文本「未读消息」→「以上是未读消息」

## 设计

### 1. 移除视口自动已读

**删除**（`web/app/src/views/Messages.vue`）：
- `maybeAutoReadVisible()` 函数（L1002-1007）
- `autoReadDebounce` 变量（L621）
- `onMsgScroll` 中的节流接入（L936-937）
- `onBeforeUnmount` 中的 `clearTimeout(autoReadDebounce)`（L719）

**保留**（复用）：
- `doMarkRead(maxId)`（L985-992）：手动全读复用
- `visibleMaxMsgId()` / `itemMaxId()` / `visibleEndIndex`：分隔线定位逻辑仍用 `currentVisibleIndex`，但 `visibleEndIndex` 目前无消费者——**保留**（未读分隔线定位备用，不删）

> 注：`visibleMaxMsgId` 移除自动已读后无调用方，但删除会增加改动面。保留（YAGNI 权衡：与分隔线定位同属可视区追踪，后续分隔线交互可能复用）。若不保留则一并删除，两者皆可——**以最小改动为原则，保留不动**。

### 2. 右下角浮动按钮：点击跳最后一条消息（最新）

**删除**：
- `jumpUnread()` 双态逻辑（未读区↑=全读、历史区↓=回第一条未读）
- `jump-btn` 模板（L284-292）的 `ArrowDown` 分支 / `inUnreadArea` 双态

**改**：
- 右下角浮动按钮：`@click="backToTop"`，icon `ArrowUp`，title「回到最新」
- 即：**只保留「回到最新」一个浮动按钮**（`backTop` 已有，`showBackTop` 控制显示）
- 「回第一条未读」能力移除（分隔线仍可见提示未读位置，进入频道仍停在未读区）

> 简化：现有 `back-top` 按钮（L280-282）已是「回到最新」。**右下角仅保留 `back-top`**，删除 `jump-btn` 整个块 + `jumpUnread` + `inUnreadArea` 相关（若 `inUnreadArea` 无其他消费者则一并删）。

### 3. 标题栏按钮调整

当前标题栏（大致）：
```
[搜索框] [只看媒体 checkbox] [下载所选] [按范围下载] [刷新]
```

改为（**从右到左**）：
```
[刷新] [全部已读*] [按范围下载] [下载所选] [只看媒体*] [搜索框]
```

- **全部已读**（新增）：`el-button`，点击弹 `ElMessageBox.confirm('确认将该频道全部标记为已读？')` → 确认后 `doMarkRead(最新消息id)` + `refreshChatsUnread()`
  - 最新消息 id：`displayItems` 第一条（倒序）的 `itemMaxId`，或 `unreadLastId`（已读分界）——用**最新消息 id** 语义更准（全读 = 读到最新）
  - 无未读（`!hasUnread`）时禁用或隐藏
- **只看媒体**：`el-checkbox` → `el-button`，`:class="{active: mediaOnly}"` 点击切换 `mediaOnly`，触发 `reloadMessages`

### 4. 加载更早消息 → 底部中央悬浮

**现状**（L273-276）：`loading-tip` 块在滚动容器下方（占布局流），`hasMore` 时显示「加载更早的消息」按钮；无更多时显示「已到最早的消息」。

**改**：
- 「加载更早的消息」按钮改为**绝对定位悬浮**在消息区底部中央（`position:absolute; bottom:12px; left:50%; transform:translateX(-50%)`，z-index 高于消息列表）
- 不占布局流：从滚动容器外移到容器上方悬浮层
- 「已到最早的消息」提示保留原占位位置（或不悬浮）
- 悬浮按钮点击仍调 `loadMore()`，`loadingMore` 时禁用显示 loading

### 5. 未读分隔线文本

`web/app/src/views/Messages.vue` L134：`<span>未读消息</span>` → `<span>以上是未读消息</span>`

## 测试

- 无前端单测基建 → `npm run build` + 浏览器实测
- E2E 实测点：
  1. 进入有未读频道 → 标题栏点「全部已读」→ 弹确认框 → 确认 → 未读归零、左侧徽标清除
  2. 取消确认框 → 未读不变
  3. 滚动浏览 → **未读线不自动变动**（无自动已读）、左侧列表**不刷新**
  4. 「只看媒体」点击 → 按钮高亮 + 只显示媒体消息；再点取消
  5. 右下角按钮点击 → 跳到最后一条消息（最新）
  6. 「加载更早的消息」悬浮在底部中央，点击加载更早消息
  7. 分隔线显示「以上是未读消息」

## 不做的事

- 不做全局「所有频道全读」（只做当前频道）
- 不移除未读分隔线/未读定位（保留，只改文案）
- 不引入新依赖

## 风险

- 移除自动已读后 `refreshChatsUnread` 只在手动全读时调用 → 左侧列表刷新次数大减，体验提升
- 「全部已读」误触有确认框兜底
- 「回到最新」与「回第一条未读」二选一：用户已确认右下角只跳最新（回第一条未读靠分隔线提示 + 进入频道停在未读区）
